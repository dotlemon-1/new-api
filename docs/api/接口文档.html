开放接口文档

面向第三方系统的对接说明：鉴权方式、转发接口、异步任务、用量查询与管理 API。
文档版本 v1.0 · 服务端版本请以 GET /api/status 返回的 version 为准。

阅读顺序建议：先阅读 鉴权方式 与 通用约定，再按业务选择 转发接口（同步对话/图片/音频）或 异步任务接口（视频/长任务）， 最后参考 调用示例。

1. 概述

本服务是一个 AI API 网关：对客户端暴露统一的 OpenAI / Anthropic / Gemini 兼容协议，对上游聚合多家模型供应商。第三方只需对接本服务的地址与令牌，无需关心上游渠道。

接口层路径前缀典型用途鉴权凭证
转发接口/v1、/v1beta、/mj对话、嵌入、重排、音频、图像、实时语音sk- 站点令牌
任务接口/v1/tasks、/v1/videos、/v1/images、/v1/responses视频生成、长耗时任务、任务产物下载sk- 站点令牌
用量查询/api/usage、/api/log、/dashboard/billing令牌额度、调用日志、账单用量sk- 站点令牌（只读）
管理 API/api账号、令牌、渠道、用户、日志、系统设置登录 JWT 或 nap_ PAT
公开接口/api站点状态、公告、定价、支付回调无

2. 鉴权方式

本服务有四种凭证，用途完全不同，请勿混用：

凭证格式适用接口有效期
站点令牌sk- + 48 位字母数字/v1、/v1beta、/mj、用量查询自定义，-1 表示永不过期
登录 Access TokenJWT/api 面板接口15 分钟
个人访问令牌（PAT）nap_ + 43 位 base62/api 面板接口（按 scope 授权）1 小时 ~ 永久
安全验证凭证X-Security-Proof 头敏感管理操作（改密、2FA、查看渠道密钥等）1 分钟

2.1 站点令牌（sk-）

站点令牌用于调用所有 AI 转发接口，按令牌计量额度、限制模型与来源 IP。

获取方式

  1. 登录控制台，进入「令牌」页面，点击「添加令牌」；
  2. 设置名称、额度、过期时间、可用模型、IP 白名单、分组后保存；
  3. 复制令牌 key，调用时拼接为 sk-<key>。

也可通过管理 API 创建：POST /api/token/。

请求头

协议请求头 / 参数示例
OpenAI 兼容（推荐）Authorization: Bearer sk-xxxAuthorization: Bearer sk-1a2b...
Anthropic 原生x-api-key: sk-xxx配合 anthropic-version 头
Gemini 原生x-goog-api-key: sk-xxx 或 ?key=sk-xxx仅 /v1/models、/v1beta/* 支持 query 传参
Midjourneymj-api-secret: sk-xxx也兼容 Authorization
WebSocketSec-WebSocket-Protocol: openai-insecure-api-key.sk-xxx可与其他子协议用逗号并列
 
curl https://api.example.com/v1/chat/completions \
  -H "Authorization: Bearer sk-1a2b3c4d5e6f7g8h9i0j" \
  -H "Content-Type: application/json" \
  -d '{"model":"gpt-4o-mini","messages":[{"role":"user","content":"你好"}]}'

令牌校验项

  • 状态：已禁用的令牌直接拒绝；
  • 过期时间：过期后拒绝（只读用量接口除外）；
  • 剩余额度：不足时拒绝（unlimited_quota=true 不受限）；
  • 模型限制：令牌开启模型限制时，仅允许白名单内模型；
  • IP 白名单：配置后仅允许指定 IP/CIDR 调用；
  • 分组：令牌可固定或自动选择分组，影响可用模型与倍率；
  • 用户状态：用户被封禁时其所有令牌不可用。
安全提示：站点令牌等同于账户额度，请仅在服务端保存，不要写入前端代码或公开仓库；泄露后请立即在控制台删除。

2.2 控制台登录（JWT）

浏览器或受信脚本可先登录换取短期 Access Token，再调用 /api 管理接口。

POST/api/user/login 无需鉴权账号密码登录
参数类型必填说明
usernamestring是用户名
passwordstring条件未开启密码加密时必填
password_encryptedstring条件开启密码加密时必填，见 GET /api/user/login/encryption-key
encryption_key_idstring条件与 password_encrypted 配套的 kid
 
{
  "success": true,
  "message": "",
  "data": {
    "access_token": "eyJhbGciOi...",
    "token_type": "Bearer",
    "access_expires_at": 1730000000,
    "user": { "id": 1, "username": "root", "role": 100 },
    "session": {
      "sid": "3f1c...", "current": true, "login_method": "password",
      "ip": "203.0.113.7", "user_agent": "curl/8.0",
      "created_at": 1730000000, "last_active_at": 1730000000, "expires_at": 1732592000
    }
  }
}

响应同时下发 HttpOnly Refresh Cookie（Path=/api/user/auth，最长 30 天）。若账号启用了 2FA、Passkey 或邮箱验证，data 会是登录挑战：

{
  "success": true,
  "data": {
    "require_verification": true,
    "flow_token": "9f2c...",
    "expires_at": 1730000300,
    "methods": [ { "method": "2fa", "available": true }, { "method": "password", "available": true } ]
  }
}

随后调用 POST /api/user/login/2fa（或 POST /api/user/login/verify）携带 flow_token 与验证码完成登录。

POST/api/user/auth/refresh Refresh Cookie轮换刷新令牌

使用浏览器 Cookie 中的 Refresh Token 换取新的 Access Token，并轮换 Refresh Token。返回结构与登录一致。

  • 可选请求头 X-Auth-Session: <sid>，与 Cookie 不一致时返回 409 AUTH_SESSION_MISMATCH，且不轮换任何凭证；
  • 启用 SESSION_COOKIE_SECURE=true 时校验 Origin，跨域脚本调用会失败；
  • 同一 Refresh Token 并发使用会确定性恢复同一后继 Token，不会互相踢下线。
POST/api/user/auth/logout Refresh Cookie登出并撤销当前会话

撤销当前登录会话并清除 Cookie；可同时携带 Authorization: Bearer。

2.3 个人访问令牌（PAT）

PAT 适合服务端自动化调用管理 API，无需保存账号密码，也不受浏览器会话限制。

  • 格式：nap_ + 43 位 base62 随机串，明文仅在创建时返回一次；
  • 创建需要浏览器会话，并完成一次 access_token.generate 安全验证；
  • 每个用户最多 20 个，默认 30 天过期，最短 1 小时，可选永不过期；
  • 每个请求都会重新读取角色与权限，管理员权限被撤回后对应 scope 立即失效。
curl https://api.example.com/api/user/self \
  -H "Authorization: Bearer nap_4f9c2b1e7a..."

资源可用动作最低角色覆盖范围

billingread / write管理员充值记录、充值确认

未声明 scope 的路由一律拒绝（403 ACCESS_TOKEN_ROUTE_UNDECLARED）；scope 不足返回 403 ACCESS_TOKEN_SCOPE_DENIED，并在 message 中给出所需 scope。

限制：PAT 不能创建、改名、撤销 PAT，也不能管理登录会话——这些接口只接受浏览器会话。

2.4 二次验证（Security Proof）

修改密码、启用/关闭 2FA、注册 Passkey、删除用户、查看渠道密钥等操作需要额外的二次验证凭证。

GET/api/verify/methodsJWT / PAT查询可用验证方式

查询参数 scope 指定操作，返回可用验证方式列表与要求。

POST/api/verifyJWT / PAT完成验证并换取 Proof
参数类型必填说明
methodstring是password / 2fa / passkey / oauth
scopestring是目标操作，如 channel.key.read
contextobject否操作上下文，如 {"user_id":12}
codestring条件2FA 动态码
passwordstring条件密码验证方式
 
{
  "success": true,
  "data": { "proof_token": "sp_9c1f...", "expires_at": 1730000060, "method": "password", "scope": "channel.key.read" }
}

随后在目标请求中携带 X-Security-Proof: sp_9c1f...，凭证 1 分钟内有效且只能用于绑定的 scope 与上下文。

3.3 状态码与错误

HTTP含义处理建议

3.4 限流

服务端按不同维度限流，触发后返回 429：

  • 全局 API 限流：按 IP 限制 /api 请求频率；
  • 敏感操作限流：登录、注册、支付、验证码等单独更严格的阈值；
  • 模型请求限流：按「用户 + 模型」限制成功请求数（可在系统设置中配置）；
  • 搜索限流：日志、令牌搜索接口。

多节点部署时若共用 Redis，限流额度在节点间共享；否则按节点独立计数。

3.5 跨域与压缩

/v1 与 /api 均启用宽松 CORS（允许任意 Origin 与凭证），浏览器可直接调用；/api 同时启用 gzip 响应压缩。

3.6 模型与渠道选择

  • 请求体中的 model 必须是某个启用渠道已配置的模型；否则返回无可用渠道错误；
  • 令牌的「分组」与「模型限制」会进一步约束可路由的渠道；
  • 同一模型可被多个渠道承载，网关按优先级、权重与负载自动选择，并在失败时重试；
  • 通过 GET /v1/models 获取当前令牌可见的模型列表。

7.8 用户管理动作：/api/user/manage

参数类型必填说明
idint是目标用户 ID
actionstring是enable、disable、delete、promote、demote、add_quota
valueint否仅 add_quota 使用：额度变更量或目标值
modestring否仅 add_quota 使用：add、subtract、override
action效果前置条件副作用
enable状态置为启用目标角色低于操作者（Root 例外）恢复登录与转发
disable状态置为禁用目标不能是超级管理员该用户所有令牌立即无法转发
delete删除用户目标不能是超级管理员；需二次验证级联删除其令牌、清空令牌缓存、撤销全部会话
promote角色升为管理员（10）仅 Root 可调用；目标当前不是管理员需二次验证
demote角色降为普通用户（1）目标不能是超级管理员，且当前是管理员清空其 Casbin 权限、重载策略、撤销全部会话

额度调整模式（action = add_quota）

mode计算方式value 约束
add余额 = 当前余额 + value必须 > 0
subtract余额 = 当前余额 − value必须 > 0；可扣成负数，但受钱包上下限约束
override余额 = value（绝对值覆盖）允许 0 与负数；绝对值不得超过钱包上限

余额变更在数据库事务中加行锁完成，只把「提交后的差值」同步到余额缓存，未结算的在途预扣额度不受影响。add_quota 不需要二次验证。

二次验证（X-Security-Proof）

delete、enable、disable、promote、demote 都需要先获取一次性凭证，再通过请求头 X-Security-Proof 提交。scope 与 context 必须与目标操作完全一致，否则返回 SECURITY_PROOF_CONTEXT_MISMATCH：

actionscopecontext
deleteadmin.user.delete{"user_id": 42}
其余管理动作admin.user.manage{"user_id": 42, "action": "disable"}

凭证有效期约 60 秒且只能使用一次（重复提交返回 SECURITY_PROOF_CONSUMED）。获取方式：

# 1) 换取一次性凭证（需浏览器会话 Cookie 或已登录的 PAT 身份）
curl -X POST "https://api.example.com/api/verify" \
  -H "Authorization: Bearer nap_xxx" \
  -H "Content-Type: application/json" \
  -d '{"method":"password","password":"your-password","scope":"admin.user.manage","context":{"user_id":42,"action":"disable"}}'

# 返回
# {"success":true,"message":"","data":{"proof_token":"p_9f2c...","expires_at":1730000060,
#   "method":"password","scope":"admin.user.manage"}}

# 2) 携带凭证执行动作（60 秒内，且只能成功一次）

9.3 排查清单

  1. 401 令牌无效：确认 header 为 Authorization: Bearer sk-...，且令牌未被禁用/删除。
  2. 403 模型不允许：令牌开启模型限制时，检查 model_limits；或改用 GET /v1/models 返回的模型名。
  3. 403 额度不足：调用 GET /api/usage/token/ 查看 total_available。
  4. 404 路径不存在：注意 /v1 与 /api 前缀区别；管理 API 部分路径带尾斜杠（如 /api/token/）。
  5. 429 限流：按 Retry-After 语义退避（若无该头，使用指数退避）。
  6. 400 敏感词 / 内容拦截：调整提示词，或联系管理员检查站点策略。
